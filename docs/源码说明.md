## 一、要解决的问题

Unity 注册页 `https://login.unity.com/zh/sign-up` 提交时恒报「验证码无效，请重试」。真实链条：

1. 页面通过 `https://www.recaptcha.net/recaptcha/enterprise.js?onload=recaptchaEnterpriseOnLoad&render=explicit` 加载 reCAPTCHA Enterprise。
2. 该加载器返回的桩代码把真正的载荷写死在国内 CDN：
   `po.src = 'https://www.gstatic.cn/recaptcha/releases/NhfdZHzre166o-vFZrWsq3yu/recaptcha__zh_cn.js'`
3. `login.unity.com` 的 **响应头** `content-security-policy` 中，`script-src` 只白名单了
   `https://www.recaptcha.net/recaptcha/` 与 `https://www.gstatic.com/recaptcha/`，**没有** `https://www.gstatic.cn`。
4. 浏览器拒绝加载 → `window.grecaptcha` 存在但 `grecaptcha.enterprise.execute === undefined` → 无 token → 服务端报「验证码无效」。

**关键点：CSP 是响应头而不是 `<meta>` 标签**，所以前端脚本无法自救，必须从「改响应头」这个层面下手——这正是本扩展采用的路径。

## 三、`manifest.json` 逐字段注释

JSON 不支持注释，这里用「代码块 + 注释表」的形式给出。**实际文件里不能写 `//`**，否则解析失败。

```json
{
  "manifest_version": 3,
  "name": "Unity Signup CSP Fix",
  "version": "1.0.0",
  "description": "为 login.unity.com 移除 Content-Security-Policy 响应头……",
  "icons": { "128": "icon128.png" },
  "permissions": ["declarativeNetRequest"],
  "host_permissions": ["*://login.unity.com/*", "*://api.unity.com/*"],
  "declarative_net_request": {
    "rule_resources": [
      { "id": "csp_rules", "enabled": true, "path": "rules.json" }
    ]
  }
}
```

| 字段 | 取值 | 为什么是这个值 |
|---|---|---|
| `manifest_version` | `3` | V3 才提供 `declarativeNetRequest` 静态规则能力；V2 的 `webRequest` 已停止受理且需要常驻后台。 |
| `name` / `version` | `Unity Signup CSP Fix` / `1.0.0` | 改动 `rules.json` 时建议同步升 version，便于在 `edge://extensions` 里确认加载的是新版。 |
| `description` | 一段中文说明 | 会显示在扩展卡片上，说明「删 CSP 头」这一行为，避免以后自己忘记。 |
| `icons.128` | `icon128.png` | 只声明 128 一档即可，Edge 会自行缩放。删掉整个 `icons` 段也能加载，只是显示默认拼图图标。 |
| `permissions` | `["declarativeNetRequest"]` | **唯一必需的权限**。它允许扩展声明/应用网络请求规则。不需要 `webRequest`（性能差、需要 host 权限且会触发更强提示），也不需要 `storage`（无任何运行时状态）。 |
| `host_permissions` | `*://login.unity.com/*`、`*://api.unity.com/*` | 修改响应头只能作用于 host 权限覆盖的域。这里刻意只列两个域，**不要**写成 `<all_urls>`——那会把 CSP 删到全互联网，是明显放大的攻击面。 |
| `declarative_net_request.rule_resources` | `id: csp_rules`、`enabled: true`、`path: rules.json` | 声明一个**静态规则集**：`id` 是规则集名字（被 `getEnabledRulesets` 之类 API 引用，随意但需唯一）；`enabled: true` 表示无需运行时调用即生效；`path` 指向规则文件，必须与 manifest 同目录（或子目录）。 |

`*://` 中的 `*` 同时匹配 `http` 与 `https`，写死 `https` 也可以，留 `*` 是为了兼容 Unity 可能的跳转。

## 四、`rules.json` 逐条注释

文件是一个**规则数组**，每条规则由 `id`、`priority`、`action`、`condition` 四部分组成。

```json
[
  {
    "id": 1,
    "priority": 1,
    "action": {
      "type": "modifyHeaders",
      "responseHeaders": [
        { "header": "content-security-policy", "operation": "remove" },
        { "header": "content-security-policy-report-only", "operation": "remove" },
        { "header": "x-content-security-policy", "operation": "remove" }
      ]
    },
    "condition": {
      "urlFilter": "||login.unity.com/",
      "resourceTypes": ["main_frame", "sub_frame", "script", "xmlhttprequest",
                        "stylesheet", "image", "font", "other"]
    }
  },
  {
    "id": 2,
    "priority": 1,
    "action": {
      "type": "modifyHeaders",
      "responseHeaders": [
        { "header": "content-security-policy", "operation": "remove" },
        { "header": "content-security-policy-report-only", "operation": "remove" }
      ]
    },
    "condition": {
      "urlFilter": "||api.unity.com/",
      "resourceTypes": ["main_frame", "sub_frame", "xmlhttprequest", "other"]
    }
  }
]
```

### 规则 1：抹掉登录页的 CSP

| 字段 | 值 | 注释 |
|---|---|---|
| `id` | `1` | 规则集内唯一整数，从 1 开始即可；删改规则时不要复用正在生效的 id。 |
| `priority` | `1` | 多条规则同时命中时的仲裁权重；这里只有两条互不重叠的规则，取值不敏感。 |
| `action.type` | `modifyHeaders` | DNR 的三种动作之一（另两种是 `block` 与 `redirect`）。只有它能在**响应方向**改写头部。 |
| `action.responseHeaders[].header` | `content-security-policy` | 就是卡住 reCAPTCHA 的那个头。注意 DNR 的头部名大小写不敏感，统一写小写便于阅读。 |
| 同上 | `content-security-policy-report-only` | 「只上报不拦截」的变体。现在没用，但 Unity 一旦切到这个模式，虽然拦截消失、报告仍会刷屏，一并删掉更干净。 |
| 同上 | `x-content-security-policy` | 上古 IE/早期 Chrome 的别名，现实中几乎不会出现，属于顺手兜底，成本为零。 |
| `action.responseHeaders[].operation` | `remove` | 另外两个取值是 `set`（覆盖值）和 `append`（追加）。`set` 需要显式给 `value`，`remove` 不需要。 |
| `condition.urlFilter` | `\|\|login.unity.com/` | DNR 的子串/Aho-Corasick 语法。`\|\|` 表示「域名起点」，`\|` 表示「串首或串尾」锚点。所以它匹配 `https://login.unity.com/zh/sign-up`、`https://sub.login.unity.com/x`，但**不匹配** `https://evil.com/?u=login.unity.com`（因为域名起点不在这里）。 |
| `condition.resourceTypes` | 含 `main_frame` 等 8 项 | **这一项最容易踩坑**：CSP 挂在「文档响应」上，若 `main_frame` 不在列表里，主文档的 CSP 头就删不掉，等于整条规则无效。其余类型（`script` 等）是为了让子资源的响应头也一并处理；`font`、`image`、`stylesheet` 属于冗余保险，多列不会放大权限（仍受 host 权限约束）。 |

> 为什么必须列全 `resourceTypes`：DNR 的 `condition` 不写 `resourceTypes` 时**默认只匹配部分类型**，且不含 `main_frame`。显式写全是最稳的做法。

### 规则 2：`api.unity.com` 兜底

| 字段 | 说明 |
|---|---|
| `urlFilter` | `\|\|api.unity.com/` |
| 用途 | 目前 token 校验不需要它；但如果 Unity 把验证码上报或 token 交换挪到 `api.unity.com`，该子域若也带 CSP，就会以同样的方式把请求拦下。加上这条，等于提前堵住同一个根因的另一个出口。 |
| `resourceTypes` | 只保留 `main_frame`、`sub_frame`、`xmlhttprequest`、`other`——API 域不会承载页面渲染资源，无需列出 `image`/`font`/`stylesheet`。 |
| 头部 | 少删了 `x-content-security-policy`，因为这是现代 API 域，不存在上古浏览器的需求。 |

## 五、它凭什么「不需要后台进程」

`declarativeNetRequest` 是**声明式**的：规则在扩展加载时被浏览器编译成内部的匹配表（即 `_metadata/generated_indexed_rulesets/_ruleset1`），请求经过网络栈时由浏览器 C++ 层直接查表决定是否改写响应头。

对比 V2 时代的 `webRequest`：

| | `declarativeNetRequest`（本扩展） | `webRequest`（旧方案） |
|---|---|---|
| 是否需要常驻页面/Service Worker | 否 | 是（阻塞式监听） |
| 是否能看到请求内容 | 否 | 是 |
| 每请求延迟 | 查表，微秒级 | 需唤起扩展进程 |
| 权限提示 | 一条「拦截内容」 | 更强，含「读取浏览记录」类提示 |

因此本扩展**没有 background script、没有 content script、没有弹出页（popup）**，三个文件即是全部。

## 六、权限与隐私边界

- 能做的：改写 `login.unity.com`、`api.unity.com` 的**响应头**。
- 不能做的：读取请求/响应体、读取 DOM、读取 cookie、读写本地存储、访问其他站点、发起任何网络请求。
- 数据流向：无。扩展不含任何 JS 代码，连 `fetch` 都不存在。

## 七、安装、更新与卸载

**安装**

1. 解压到固定目录（例：`C:\Tools\Unity-CSP-Fix-v1.0.0`）。
2. `edge://extensions` → 打开「开发人员模式」。
3. 「加载解压缩的扩展」→ 选择含 `manifest.json` 的那一层目录。
4. 打开注册页按 `Ctrl+F5` 强刷（旧页面的 CSP 头仍在缓存里）。

**更新规则**

改 `rules.json` → `edge://extensions` 点该扩展卡片的「重新加载」。只改文件不点重载，旧的编译规则仍然生效。

**卸载**

卡片上「删除」。或在文件管理器中删目录后 Edge 会显示为「损坏/已移除」。

在不改动 Unity 服务端的前提下，可用 CDP 观察（仅用于自测，日常不需要）：

| 检查项 | 未装扩展 | 装扩展后 |
|---|---|---|
| 文档响应头 `content-security-policy` | 存在 | 不存在 |
| `www.gstatic.cn/.../recaptcha__zh_cn.js` | `blockedReason: "csp"`，未发出 | 200 |
| `grecaptcha.enterprise.execute` | `undefined` | 存在（函数） |
| `/recaptcha/enterprise/anchor`、`/bframe` | 无 | 200 |
| 提交后的提示 | 「验证码无效，请重试」 | 不再出现 |

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `无法加载扩展` / `Manifest is not valid JSON` | JSON 存成了 UTF-8 **带 BOM**，或写了 `//` 注释 | 用「UTF-8 无 BOM」另存；去掉注释 |
| 扩展显示「已停用」 | 「开发人员模式」被关掉 | 重新打开开发人员模式 |
| 装好了但页面仍旧报错 | 没有强刷；或浏览器复用了旧文档 | `Ctrl+F5`；仍不行则在 `edge://extensions` 点「重新加载」后再刷 |
| 装好了、页面不报错，但仍然注册失败 | 已不是 CSP 问题（可能触发了服务端风控/邮箱已注册） | 看 DevTools Network 里 `/zh/sign-up` 的响应内容 |
| 换机器后 ID 变了 | unpacked 扩展 ID 由绝对路径派生 | 正常现象，不影响功能 |

## 十、和其他绕行方案的对比

| 方案 | 优点 | 缺点 |
|---|---|---|
| **本扩展（DNR 删 CSP 头）** | 无需改浏览器启动参数、无后台进程、作用域最小 | 需要保持「开发人员模式」开启；仅 Chromium 可用 |
| `--load-extension` + `Page.setBypassCSP`（调试用） | 无需安装任何东西 | 只对调试实例生效，且要开调试端口，日常不可用 |
| Header Editor / ModHeader 类扩展 | 图形化配置 | 权限更大、规则易误伤其他站点 |
| 改用 Google / Apple / SSO 注册 | 完全绕过该验证码 | 需要相应的第三方账号 |
| 等 Unity 修 CSP | 治本 | 不可控；官方 CSP 只需补 `https://www.gstatic.cn/recaptcha/` |

> 本扩展只是**客户端绕行**。根因是 Unity 前端 CSP 少了一个白名单域，正确修复仍应由服务端完成。
