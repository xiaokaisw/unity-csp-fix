# 演示视频分镜脚本

> 目标时长 **2 分 30 秒**（允许 2:00–3:30）。重点不是「装了插件就好了」，而是**如何从一句错误提示走到可验证的结论**。

## 一、录制前准备

| 项 | 说明 |
| --- | --- |
| 分辨率 | 1920×1080 或更高，浏览器缩放 100%，页面元素看得到即可 |
| 浏览器 | Edge，**用一个干净的独立 profile**（不要用日常 profile，避免登录态/扩展干扰） |
| 标签页 | 只留两个：① `https://login.unity.com/zh/sign-up` ② DevTools（Console + Network） |
| 清理 | 先按 F12 打开 DevTools 并停靠在右侧；`Ctrl+Shift+Delete` 清缓存后再开始 |
| 麦克风 | 有则用；无则全程加字幕，字幕内容即为下方「旁白」 |
| 录屏 | Win+Alt+R（Xbox Game Bar）或 OBS；结束后导出 mp4 |

> 注意：2026-10-29 复查时站点已切换 CSP 策略，**线上已不再复现**。
> 因此视频第 2 段「复现」有两种拍法：
> **A（推荐）** 用 `verify/run.ps1 -NoExtension` 起旧策略环境的对照输出 + 历史截图讲解，明确说明「这是修复当时的真实记录」；
> **B** 只讲逻辑与验证工具，不伪造现场复现。
> **不要**为了画面效果去 P 图或伪造控制台报错——一旦被对照 `verify.mjs` 的真实输出就会发现矛盾。

## 二、分镜

### 0:00–0:20　钩子

- **画面**：注册页表单已填好，鼠标点「创建帐户」，4 秒后出现「验证码无效，请重试」。
- **旁白**：「注册 Unity 账号，卡在这一句提示上。换邮箱、换密码、换浏览器、重试十几次——都没用。因为这句话在撒谎。」

### 0:20–0:50　排除法：先证明「不是你的错」

- **画面**：切 DevTools → Network，点提交，高亮 `POST /zh/sign-up` 返回 **200**；再切 Console，滚到红色 CSP 报错，鼠标圈出 `www.gstatic.cn/.../recaptcha__zh_cn.js` 与 `script-src ...`。
- **旁白**：「提交在 HTTP 层是成功的，200。真正的错误在控制台：验证码脚本被 CSP 拦下了。注意——请求没发出去，`blockedReason: csp`。所以不是网络，不是你填错，也不是被墙。」

### 0:50–1:30　根因：一条白名单漏了一个域名

- **画面**：打开 `docs/原理分析.md` 的链条图（五步），或手写板画 ①→⑤。
- **旁白**：「加载器来自 recaptcha.net，但它返回的桩代码把真正的脚本写死在 `www.gstatic.cn`；而页面的 CSP 白名单里只有 `gstatic.com` 和 `recaptcha.net`。浏览器拒绝加载 → `grecaptcha.enterprise.execute` 是 undefined → 服务端拿不到 token → 回你一句『验证码无效』。」

- **画面**：切到 CDP 反证 —— 跑 `verify.mjs` 对照表（旧策略 blocked: csp / 200）。
- **旁白**：「只放行这一页的 CSP，其余不变，脚本立刻 200，anchor、bframe 全部 200，那句提示消失。单变量翻转，结论就锁在这里。」

### 1:30–2:00　修复：3 个文件，2 条规则

- **画面**：`edge://extensions` → 开发人员模式 → 加载解压缩的扩展 → 选 `extension/`；展示扩展卡片与「已启用」。再打开 `extension/rules.json` 高亮两条规则。
- **旁白**：「修复不需要写脚本。两条 declarativeNetRequest 规则，只在 login.unity.com 和 api.unity.com 上移除 CSP 响应头。没有后台进程，没有内容脚本，读不到你的密码，也不联网。三个文件，一共不到 2KB 代码。」

### 2:00–2:25　验证：把结论写成断言

- **画面**：终端 `powershell -File verify/run.ps1` → `node verify/verify.mjs --port 9333 --expect load` → 输出 PASS。
- **旁白**：「验证不靠截图。脚本直连 DevTools 协议，观察真实网络和控制台，输出 load 或 block。加 `--expect load`，它就变成一条会失败的断言——站点哪天回退，CI 会先报错。」

### 2:25–2:30　收尾

- **画面**：仓库首页 + 一句标题。
- **旁白**：「一个看起来该由用户重试的错误，实际是一条漏写的白名单。修好它用了两条规则；证明它修好了，用了一条断言。」

## 三、可选加分镜头

- 展示 `docs/对话记录.html`：完整的排查过程（含走过的弯路）。
- 展示 `verify.mjs` 的 `policyType` 判定：`none` / `nonce+strict-dynamic` / `host-allowlist`，说明**同一 URL 两周内两种策略都出现过**，所以工具必须保留双向判定。
- 展示 2026-10-29 复查结论：站点已自愈，扩展不再是必需品——**敢说自己的补丁已经过期，比硬说它一直有用更可信**。
